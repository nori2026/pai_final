## 1. 課題の概要

Gazebo（Fortress）上の差動二輪ロボットにカメラを取り付け、カメラ画像を AI（YOLOv8、学習済みモデルによる推論）で解析し、**人を見つけて自動で追いかける**システムを ROS 2（Humble）で作った。

ベース：「gazeboとROS2を連携してロボットを操作する」（Qiita, N622）
https://qiita.com/N622/items/9d89f77d85d9da0af29e

## 2. 目的

- 記事で学んだ「ROS 2 から Gazebo のロボットを動かす」方法を、人がキーで操作する形から **AI が自分で判断して動く形** に発展させる。
- 応用例：介護施設や病院での見守り・付き添いロボット、荷物を運んで人について行く運搬ロボット、店舗での案内ロボットなど。

## 3. システム構成

（README の構成図、またはスクリーンショットを貼る）

| ノード / 部品 | 役割 |
|---|---|
| Gazebo（follow_world.sdf） | ロボット・カメラ・人・障害物のシミュレーション |
| ros_gz_bridge（bridge.yaml） | `/cmd_vel`、カメラ画像、オドメトリを ROS 2 ⇔ Gazebo で変換 |
| person_follower | YOLOv8 で人を検出し、速度指令を計算 |
| person_mover | 人を8の字に歩かせる（デモ用） |

## 4. AI の使い方

- モデル：YOLOv8n（COCO データセットで学習済み、`person` クラスのみ使用）
- 推論のみ（追加学習なし）。CPU でも動くように一番小さいモデルを選んだ。
- 検出した枠（バウンディングボックス）から
  - 枠の中心の左右のずれ → 旋回速度
  - 枠の高さ（画像に対する割合）→ 距離の目安 → 前進速度
  を計算した。

## 5. ベース記事からの工夫点（★必ず書く：丸写しでないことを示す）

1. **入力をキーボードからカメラ＋AIに変更**：カメラセンサーを SDF に追加し、Sensors プラグインを有効にした。
2. **ブリッジ設定の拡張**：記事の `/cmd_vel` に加えて、カメラ画像（Gazebo→ROS 2）とオドメトリを config ファイルで変換した。
3. **状態に応じた行動**：FOLLOW / REACHED / WAIT / SEARCH の4状態。見失ったら最後に見えた方向へ回って探す。
4. **安全のための工夫**：速度の上限、近づきすぎたら少し下がる、ずれが大きい時は旋回を優先して前進を弱める。
5. **動画で分かりやすく**：AIの視界（検出枠・状態・速度）を描いた画像を `/ai/debug_image` に出し、画面に表示した。人を自動で歩かせるノードも作った。
6. **起動を1コマンドに**：launch ファイルで Gazebo・ブリッジ・AI・表示をまとめて起動。

## 7. うまくいかなかった点・反省と考察

（例）
- 人が速く動くと見失うことがあった → 推論が遅い（CPU）ため。GPU を使う、画像を小さくする等で改善できそう。
- 箱の後ろに人が隠れると追えない → 最後に見えた位置を覚えて移動する機能があるとよい。
- 距離を画像の大きさで推定しているので、しゃがんだ人だと誤差が出る → 深度カメラや LiDAR と組み合わせるとよい。
